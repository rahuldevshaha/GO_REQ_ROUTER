Go Router API

Lightweight router that checks Main Load Balancers and redirects clients to a healthy endpoint.

http://localhost:8080

API Endpoints

GET /

Returns this API documentation page.

GET http://localhost:8080/

Response:

HTML document

GET /health

Checks whether the Router itself is running.

GET http://localhost:8080/health

Response:

HTTP/1.1 200 OK

router ok

GET /route

Checks the configured Main LB endpoints and redirects the client to a healthy Main LB. 

GET http://localhost:8080/route

Healthy LB response:

HTTP/1.1 307 Temporary Redirect
Location: https://lb2.example.com

The client/browser follows the Location automatically. The Router does not proxy the actual traffic.

503 — No Healthy Main LB

If every configured Main LB fails its health check:

HTTP/1.1 503 Service Unavailable

No healthy Main LB available

Main LB Configuration

Main LB endpoints are stored in mainLBserver.json. 

[
  {
    "name": "main-lb-1",
    "url": "https://lb1.example.com",
    "enable": true
  },
  {
    "name": "main-lb-2",
    "url": "https://lb2.example.com",
    "enable": true
  },
  {
    "name": "main-lb-3",
    "url": "https://lb3.example.com",
    "enable": false
  }
]

Enable / Disable

enable: true means the Main LB is eligible for routing. enable: false completely excludes it from routing, even when its health check is successful.

Request Flow

Step Action
1 Client calls /route
2 Router checks Main LB health
3 Router selects a healthy LB
4 Router returns HTTP 307 redirect
5 Client connects directly to the selected LB

Client Integration

The client does not need to know the Main LB addresses. It only calls the Router endpoint. 

Client
  |
  | GET /route
  v
router.example.com
  |
  | 307 Temporary Redirect
  | Location: https://selected-lb.example.com
  v
Client connects directly to selected Main LB

Client Request

GET https://router.example.com/route

Router Response

HTTP/1.1 307 Temporary Redirect
Location: https://main-lb-2.example.com

Browsers and normal HTTP clients can follow the redirect automatically. After the redirect, the client communicates directly with the selected Main LB, so Router does not carry the stream/download response traffic.

Browser Example

fetch("https://router.example.com/route")
  .then(response => {
    // The HTTP client/browser follows the redirect.
    return response;
  });

Important

Multiple Router instances need an entry/distribution mechanism so that router.example.com can reach Router 1, Router 2, Router 3, etc. Simple DNS round-robin distributes DNS answers but does not understand Router load or health. For health/load-aware routing, use a dedicated routing/load-balancing mechanism.

Client-Side Implementation

The recommended client flow is to ask the Router for a Main LB when a server selection is needed, then reuse the selected Main LB for normal API requests. If the selected LB becomes unavailable, request a new route from the Router.

Using Fetch

async function getMainLB() {
  const response = await fetch(
    "https://router.example.com/route",
    { redirect: "manual" }
  );

  if (response.status !== 307) {
    throw new Error("No healthy Main LB available");
  }

  return response.headers.get("Location");
}

async function callAPI(path) {
  const baseURL = await getMainLB();

  const response = await fetch(baseURL + path);

  if (!response.ok) {
    throw new Error("API request failed");
  }

  return response.json();
}

// Example
const movie = await callAPI("/movies/123");

Using Axios

import axios from "axios";

async function getMainLB() {
  const response = await axios.get(
    "https://router.example.com/route",
    {
      maxRedirects: 0,
      validateStatus: status => status === 307
    }
  );

  return response.headers.location;
}

async function callAPI(path) {
  const baseURL = await getMainLB();

  const response = await axios.get(baseURL + path);

  return response.data;
}

// Example
const movie = await callAPI("/movies/123");

Recommended LB Reuse

Do not call /route before every normal request unless that behavior is specifically required. The client can keep the selected Main LB and use it for requests such as login, movie details, search, etc. 

Client
  |
  | /route
  v
Router
  |
  | 307 + Location
  v
Main LB 2
  |
  +---- /login
  +---- /movies/123
  +---- /search?q=...
  +---- /profile

If Main LB 2 fails:
Client
  |
  | /route
  v
Router
  |
  | 307 + Location
  v
Main LB 1

Important: Browser CORS

If browser JavaScript reads the redirect response manually, configure CORS on the Router and allow the required client origin. Alternatively, the application can use a normal HTTP redirect flow where the browser follows the redirect automatically.
