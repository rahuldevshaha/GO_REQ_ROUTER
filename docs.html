DNS distributes clients across the Router instances. Each Router independently checks the configured Main LBs and selects an enabled, healthy Main LB.

All Router instances should use the same Main LB configuration so they can make consistent routing decisions.

2. API Endpoints

GET/

Returns this API documentation page.

GET __BASE_URL__/

GET/health

Checks the health of the Router itself.

GET __BASE_URL__/health

HTTP/1.1 200 OK

router ok

GET/route

Selects an enable: true Main LB that passes the health check and redirects the client to it. 

GET __BASE_URL__/route

HTTP/1.1 307 Temporary Redirect
Location: https://lb2.example.com

The Router does not proxy the actual application/stream traffic.

503 — No Eligible Main LB

If no enabled Main LB is healthy:

HTTP/1.1 503 Service Unavailable

No enabled healthy Main LB available

5. Client Integration

The client calls the Router when it needs a Main LB. After receiving the redirect/selected LB, it can use that Main LB directly for normal API calls.

Axios

import axios from "axios";

async function getMainLB() {
  const response = await axios.get(
    "__BASE_URL__/route",
    {
      maxRedirects: 0,
      validateStatus: status => status === 307
    }
  );

  return response.headers.location;
}

async function callAPI(path) {
  const baseURL = await getMainLB();
  const response = await axios.get(baseURL + path);
  return response.data;
}

const movie = await callAPI("/movies/123");

Recommended Reuse

Client
  |
  +-- /route
  |      |
  |      +--> Main LB 2
  |
  +-- /login       → Main LB 2
  +-- /movies/123  → Main LB 2
  +-- /search      → Main LB 2

There is normally no need to call /route before every request. Reuse the selected Main LB until it becomes unavailable.

6. Client Failover

If the selected Main LB fails, request a new route from the Router and retry the request with the newly selected Main LB. 

Client → Router → Main LB 2
                     |
                     X
                     |
Client → Router → Main LB 1 → Success
async function requestWithFailover(path) {
  let baseURL = await getMainLB();

  try {
    return (await axios.get(baseURL + path)).data;
  } catch {
    baseURL = await getMainLB();
    return (await axios.get(baseURL + path)).data;
  }
}
Keep retries limited. Do not retry indefinitely.

7. Multiple Router Setup

For multiple Router instances, expose them behind the same hostname.

api.example.com
      |
      v
     DNS
   /  |  \
  /   |   \
 R1   R2   R3
  \   |   /
   \  |  /
    Main LBs

With simple DNS round-robin, DNS can return different Router addresses. DNS itself does not select the Main LB. The selected Router performs the Main LB health/enable check.

8. Free DNS — Cloudflare Round-Robin Setup

Cloudflare DNS Free can be used to distribute clients across multiple Router instances using multiple DNS A records with the same hostname. Cloudflare documents this as simple DNS round-robin.

This is DNS distribution, not full health-checked load balancing. If a Router goes down, DNS round-robin may still return its address until DNS/cache behavior changes. The Router itself handles Main LB health checks after a client reaches it.
Using Render (or any host that only gives you a hostname like router1.onrender.com, not a static IP)? The A-record setup below needs a fixed IPv4 address per Router. Jump to Render Deployments (No Static IP) instead.

What you need

1. A registered domain
2. Cloudflare account
3. Multiple Router instances with public IPv4 addresses
4. The same Router application/config on each instance

Step 4 — Why DNS only?

For this architecture, DNS only lets DNS return the Router IPs directly. If you intentionally put the records behind Cloudflare's proxy, the client connects to Cloudflare instead and the traffic path changes.

Step 6 — Test DNS

After DNS propagation, check that the hostname resolves to the Router IPs.

nslookup api.example.com

# or

dig api.example.com

Because DNS caching and resolver behavior exist, you should not expect every client request to rotate perfectly between Router 1, Router 2 and Router 3. Round-robin DNS is simple distribution, not precise request-level balancing.

Important: Router health vs DNS health

LayerResponsibility
Cloudflare DNSDistributes DNS answers across Router IPs
RouterChecks Main LB enable + health
Main LBHandles the actual application/API traffic

Cloudflare's Free DNS round-robin setup does not replace a health-checked load balancer. For automatic removal of failed Router nodes from DNS answers, use a DNS/load-balancing service with health checks.

8b. Render Deployments (No Static IP)

Render (and most PaaS platforms) does not give free services a fixed public IPv4 address. Each deployment instead gets its own hostname: 

router1.onrender.com
router2.onrender.com
router3.onrender.com

This breaks the A-record round-robin approach in Section 8, since there is no IP to point multiple A records at. It cannot be worked around with multiple CNAME records either — DNS only allows one CNAME per hostname, and Cloudflare rejects a second CNAME on the same name. 

api    A     203.0.113.10             ✓ works (round-robin)
api    A     203.0.113.20             ✓ works (round-robin)

api    CNAME router1.onrender.com     ✓ works alone
api    CNAME router2.onrender.com     ✗ rejected — only one CNAME per name

So a single hostname like api.example.com cannot transparently round-robin across several *.onrender.com Routers using free DNS alone. Two practical options:

Option A — Give each Router its own subdomain, let the client pick

Point one CNAME at each Router:

router1.example.com  CNAME  router1.onrender.com
router2.example.com  CNAME  router2.onrender.com
router3.example.com  CNAME  router3.onrender.com

The client keeps a small list of Router URLs instead of relying on DNS to distribute traffic, and applies the same pick/retry logic already used for Main LB failover: 

const ROUTERS = [
  "https://router1.example.com",
  "https://router2.example.com",
  "https://router3.example.com",
];

function pickRouter() {
  return ROUTERS[Math.floor(Math.random() * ROUTERS.length)];
}

async function getMainLB() {
  const base = pickRouter();
  const response = await axios.get(`${base}/route`, {
    maxRedirects: 0,
    validateStatus: status => status === 307,
  });
  return response.headers.location;
}

This stays entirely on free tiers, but the Router-selection logic moves from DNS into the client.

Option B — Cloudflare Load Balancing (paid)

Cloudflare's Load Balancing product supports pools of origins addressed by hostname (not just IP), with active health checks and automatic failover — the direct replacement for round-robin A records when your origins are hostnames like *.onrender.com. It is a paid add-on, not part of the Free plan.

ApproachCostDNS complexityHealth-aware
Option A: client-side listFreeLowNo (client retries on failure)
Option B: Cloudflare Load BalancingPaidLowYes
A-record round robin (Section 8)FreeLowNo — requires static IPs, not available on Render

For a small number of Routers, Option A is usually the simplest starting point.
